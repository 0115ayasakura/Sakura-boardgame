# Sakura 插件开发：可复用经验与最小验收

依据 [README](../README.md)、[Agent 协调器](../sakura_boardgame/agent_turns.py)、[插件入口](../sakura_boardgame/plugin.py)、[动作事务](../sakura_boardgame/action_protocol.py)、[发行构建](../tools/build_release.py)和 [Registry 源树构建](../tools/build_registry_source.py)，及 1.0.2 之后的开发与实机验证整理，随 **1.0.3-pre** 归档。连续选择、意图门控、暂停和界面恢复是本次新增能力，不表示旧版已经提供；宿主分段协议修改仍不属于插件包。

## 一、先划清宿主与插件边界

通过宿主服务注册工具、上下文、设置和清理回调，以目标版本文档、真实 Schema 注册器和运行结果核对契约。`context.get`、`context.effect` 等是接入点，不保证所有版本兼容。实验性或 `v0` 接口隔离适配，缺失时明确降级，不虚构 API。

`token`、`version`、`gameSeq`、`legalAction`、`continuation`、`playPaused`、`uncertain` 以及 `boardgame_*` 工具名是**本项目协议**，不是宿主稳定 API。当前输入字段 `current_input` 也须核对目标宿主提供的上下文请求契约，不能要求所有插件照搬。迁移的是约束与测试方法，而非字段名和内部常量。

## 二、工具是授权执行，不是口头声称

模型负责选择与表达，引擎负责合法性、随机数和结算。口头声称不是执行凭据，成功回执及权威状态才算数。工具描述说明调用条件、参数和失败后停止，服务端仍须验证，提示不能代替权限检查。只读询问不隐式开局或走棋，算法备用须显式选择。

本项目采用单票单动作：票据绑定 `version`、对局代际 `gameSeq`、session/character identity、合法动作、TTL 与进程 epoch。状态改变、身份切换、超时、重载或卸载使旧票失效；票据不是存档，也不是可公开记录的凭据。先读本票状态，再提交本票动作。

掷骰后的选路、购物仅在成功回执返回 `continuation` 时签发 fresh 票，逐票重读状态；限同一业务 turn 的已知分支，**不跨新 turn，不自行开始下次掷骰**。无续票就停止，保护上限按业务设计，不照搬链长或固定工具预算。

## 三、事务完成后再找宿主，未知结果先核态

宿主 identity 查询、忙闲轮询、模型提交等 RPC 放在业务锁外；返回后重新持锁核验原意图，防止等待期间换局、换角色。后台调度必须在外层事务成功、释放锁之后启动，否则保存失败也可能派出任务，慢 RPC 还会卡死网页轮询。

事务覆盖引擎状态、版本、临时效果、RNG、票据及回执。嵌套失败不能让外层部分提交；保存失败整体回滚，不能还原棋盘却消耗随机序列。相同标识和参数返回原回执，换参数拒绝。说明去重缓存容量、持久化范围和失效条件，不宣称无限期 exactly-once。

宿主配置是独立持久资源，不能假装与游戏文件存在跨资源原子提交。持久化后的通知失败也不应反向撤销已落盘动作。异步通知如需宿主 RPC，同样应锁外派发。网络断开不等于动作失败：`uncertain` 时先取得请求之后的新权威状态，确认是否生效；旧轮询或重新渲染都不算核态，**不得自动重发未知结果的操作**。

## 四、业务事实与界面呈现分离

服务端是业务真相；客户端用一个唯一呈现 FSM 管理排队、确认、入场、返程和结算，别让弹窗、计时器、3D 模块各自再发明一套流程。引擎已结束，不代表最后事件已读、镜头已恢复或可以解锁输入。

黑列车的教训是：普通落地与公告结束后才入场；逐条确认最后结果后才返程；地图和相机转换完成后才显示结算并解锁。重要结果明确确认，轻提示才自动收起。确认按钮、计时器、Promise 返回都绑定卡片/事件及局代际，旧回调不能关闭新卡、复活旧事件或重复提交。暂停是业务授权边界，收起是展示动作；恢复不能直接消费 pending、派发聊天或清空未读队列。等待区应区分模型忙、网络异常和等待人工确认。

## 五、按当前意图注入，不让存档占领聊天

存档、旧 history、长期记忆或页面开启，不等于正在使用插件。后续 builder 仅在本轮涉及桌游或插件主动请求时注入快照，普通聊天不持续灌规则和事件。关键词门控不是完美意图识别，须测同义表达和歧义。

对照“无关话题→只读询问插件→再换话题”，检查实际 provider 关闭、开启、再关闭，业务版本不变。停止注入不等于删除旧历史，也不保证模型不提过去。无有效票的复盘不可调用票据工具。

## 六、提示跨层检查，短答不靠硬截断

工具描述、引导、角色提示及宿主普通/Agent 协议可能冲突：先解说还是先执行、用户要一句还是强制多段。检查整轮实际请求，统一为先完成授权动作再据回执回应，事实与感受分开，用户记录不混工具指令。

允许完整短答，保留复杂回答能力，不硬截断句子、翻译和语音，不新增无界重试。提示只能改善倾向，仍可能多段、跑题或失真；单个模型成功不构成效果保证。

## 七、压缩表示，不压掉权威事实

[Agent 快照编码](../sakura_boardgame/agent_snapshot.py)只对完全相同的历史玩家事实去重引用，保留行动顺序及其他全部字段；不能用当前余额或产权替代历史事实，也不能以摘要删掉不利记录。编码注明格式版本、引用读法并验证 JSON 往返无损、解码对象无共享别名；不顺手改存档与 UI 协议。

区分 UTF-8 字节数、字符数与模型 tokens。离线满历史样本和真实请求的缩减比例不可混报；字节减少不能直接声称 tokens 同比减少，更不能声称根治超时。应比较整个真实请求，而不只比较某个压缩字段。

## 八、证据要能区分“发生了什么”

测试前固定版本、场景、起止时间或日志区间、初始状态及不变量，用请求/任务/回执标识关联。公开材料仅留脱敏摘要，不复制凭据、私人聊天、角色内容或个人路径。

区分新执行与 history 回灌、宿主受理与引擎提交、模型完成与 TTS 合成、合成成功与播放 `finished`。按 recording/task 标识核对；播放日志也不等于人工听感验收。不滚动扩窗挑成功片段或混入其他轮次。

## 九、发行检查实际输入，不只检查 ZIP 大小

本项目导出根目录含清单 `plugin.yaml` 和入口的 Registry 发行源树，不直接提交开发根目录；手动 ZIP 布局另验。已核对的官方 validator 快照限制入包总量 32 MiB、单文件 16 MiB，另查数量、路径与清单；**发布时以官方 validator 当前实现为准**，压缩 ZIP 体积不能替代解压体积。

Registry 按登记的 source commit 抓取源码并重建包，release tag 和附件面向发行展示，二者不能互相代替。核对提交里的真实目录、版本、入口和资源，再验证解包内容与哈希；不要仅因 tag 存在就声称市场包正确。

采用白名单排除配置、存档、缓存、日志、测试和调试产物。缩纹理要说明画质取舍并复核资源清单。代码许可不覆盖美术，逐项说明第三方资产来源、可分发范围及替换机制；[第三方声明](../sakura_boardgame/THIRD_PARTY_NOTICES.md)随实际依赖更新，不能笼统宣称全包原创或 MIT。

## 十、Windows 本机调试的实用边界

显式选择真实 Python/Node 可执行文件，不依赖可能只是 WindowsApps 别名的 `python`；可执行文件路径通过参数或环境传入，不硬编码到公开插件。中文文本按 UTF-8 显式读写；PowerShell 的旧默认编码、数组输出和内联 JavaScript 引号都可能让诊断结果失真，复杂脚本优先落文件后执行。异常退出先查真实错误，不能把解释器或测试依赖缺失当成产品失败。

实机复现先记录现有进程、棋局与用户草稿，不擅自切换模型或修改凭据；使用隔离浏览器配置和本机调试端口，测试后关闭临时端口、恢复正常启动，不遗留演示模式或后台调度。

## 十一、新插件起步顺序与交付清单

先做一个“只读状态→一次授权动作→可靠回执”的纵向闭环，再补失败恢复；随后接当前意图上下文、最小 UI 和必要 FSM，最后扩展业务、资产与发行。只为实际风险增加机制，不先建设庞大平台。

最小交付检查：

- [ ] 在目标宿主核对服务、Schema、权限、生命周期；卸载后无遗留线程、端口和有效票。
- [ ] 覆盖错参、过期、换身份/换局、重放与异参拒绝；连续子选择不会跨新 turn。
- [ ] 注入保存失败验证状态、RNG、票据和回执回滚；模拟丢响应验证先核态、不自动重发。
- [ ] 覆盖旧回调、双击、暂停恢复、逐条确认、返程及终态；离屏页面不能代替可见 3D 验收。
- [ ] 完成无关/相关/再无关的上下文对照，检查实际提示、业务不变量与完整语音生命周期。
- [ ] 分列离线、生产代码隔离测试和正式安装真机证据，记录失败、跳过及未覆盖分支；切换供应商、模型或协议后重测工具选择、长上下文和输出格式，不外推单模型结论。
- [ ] 用当前 validator 验证真实发行 commit、安装包和升级路径，核对隐私、许可与 notice。需要宿主 patch 的改进单列宿主版本与部署要求：**宿主 patch 不属于插件发行包**，只更新插件不能保证获得该效果。
